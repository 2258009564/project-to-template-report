# 更适合哈理工宝宝体质的 Word 报告 Skill

**交给它模板和材料，说一句话，把写报告、改表达、套格式和检查页面交给 AI。**

课程报告、实验报告、课程设计，麻烦的往往不止是“写点内容”：老师给的封面不能动，正文得按模板来，目录要能更新，图表要放得下；换一次会话，又得重新交代姓名、学号和自己的要求。

`project-to-template-report` 把这些事串成一套工作流程：读懂模板 → 整理材料 → 编写正文 → 自主审稿 → 写入 Word → 检查版式。它还会在你授权后记住常用信息和明确反馈，让下一份报告更贴合你的习惯。

## 一句话开始，等报告完成

准备好模板、任务要求和事实材料，在能够调用本地文件与工具的 AI 助手里说：

> 用这个 Skill，按老师的模板和我提供的材料完成报告。保留封面和格式，正文先审稿再写入 Word，最后检查每一页，给我可编辑的 Word 文件。

后续的模板分析、内容组织、表达修订和排版核验，由助手按技能流程继续完成。需要补充的关键信息会明确指出；已有且一致的个人资料，直接复用。

**“一句话”是使用入口。** 模板、材料和本地运行环境准备好，才能让这套流程顺畅跑起来。

## 为什么说“更适合哈理工宝宝体质”

因为报告可以有固定模板，助手也应该逐渐熟悉你的要求。这里的客制化，落在三件具体的事上。

### 你说过的信息，下次接着用

姓名、学号、班级、专业等常用字段，可以在授权后留在本地档案里。下次制作报告时先读档案，避免反复追问；你更新过的信息以最新说明为准，教师、日期和组员仍按本次任务核对。

### 你指出的问题，下次少犯一次

“这段太空泛”“不要把还没实现的功能写成做完了”“这个要求只针对本次模板”——明确反馈会形成带有适用范围的本地记录。后续任务读取相关记录，把你纠正过的问题纳入写作和检查标准。使用越多、反馈越明确，可复用的个人偏好就越完整。

### 模板跟着老师走，表达贴着你的要求改

优先保留原模板的封面、章节、页眉页脚与指定保护区域，正文按实际格式组织。通用习惯、个人偏好和本次要求有冲突时，以当前明确要求为准，避免拿同一套排版硬套所有作业。

这套定位来自课程报告里反复出现的实际需求，其他学校的同学也可以带上自己的模板使用。

## 从文案到成品，它能做什么

| 环节 | 交给助手的工作 |
| --- | --- |
| 读模板 | 提取实际生效的字体、字号、段落、章节和表格格式，划清可编辑范围。 |
| 写内容 | 根据任务材料组织正文；项目报告可结合实际代码与测试证据，区分已实现、已测试和规划内容。 |
| 先审稿 | 单独进入审稿阶段，检查语义、逻辑、重复、术语和事实一致性，修复并复核后再写入 Word。 |
| 套格式 | 按语义角色批量处理标题、正文、表格和图片，生成可更新的真实目录。 |
| 查页面 | 更新字段和分页，检查封面、目录、图表、页码及文字溢出，逐页核对最终版式。 |
| 留习惯 | 在授权后把个人资料和反馈留在本地，供后续任务继续使用。 |

需要图示时，还可以按任务要求组织流程图、架构图或 UML，并检查图中内容与正文、项目事实是否一致。额外的绘图、渲染工具按需配置。

## 怎么用

### 1. 把 Skill 交给你的 AI 助手

下载本仓库，保留 `SKILL.md`、`references/` 和 `scripts/` 的目录关系。支持 Skills 的工具可以按自身规则导入；也可以让具备本地工具权限的助手读取 `SKILL.md`，再按其中流程执行。

**不限定某一个 AI 产品。** 能否完整运行，取决于所用助手能否加载说明、读写本地文件并调用所需工具；不同宿主尚未逐一验证。仅能聊天、无法访问本地文件或执行工具的界面，不能独立完成自动生成。

### 2. 准备本地环境

内置 Word 自动化脚本需要 **Windows + Microsoft Word + PowerShell**；Python 辅助脚本用于结构检查。页面检查还需要可用的文档渲染器，或将 Word 导出的内部 PDF 转成页面图片的工具。仓库不包含 `render_docx.py`，最终分页以 Word 为准。

### 3. 给出模板、要求和材料

把老师的模板、作业要求、正文素材或项目位置交给助手，再用前面的一句话启动。首次使用时，可以顺手告诉它：

> 我授权你把常用个人信息和我对 Word 报告的明确偏好记在本地，后续相关任务直接复用；只针对本次任务的要求不要当成长期习惯。

已有模板按原件保留，在副本上编辑。只改格式的任务保留原文；需要重写时，再明确可修改的内容范围。

## 记住你，也把隐私留在本地

个人信息与反馈记录放在 **Skill 目录之外**，不会因为分享这份技能而一起公开。仓库提供的是记忆规则，不包含作者的个人档案。

当前默认记录位置为 `$CODEX_HOME/memories/extensions/ad_hoc/notes/`，未设置该变量时使用 `~/.codex/memories/extensions/ad_hoc/notes/`。这是现有流程沿用的本地路径约定；使用其他宿主时，也需要让助手能够访问该位置。`word-report-profile-v1` 标记个人档案，`word-report-learning-v1` 标记反馈记录。

“学习”通过后续任务读取本地笔记实现，不涉及模型训练，也不会在会话结束后自行运行。你可以要求不记录或撤回授权；分享技能时，只分享仓库文件，别把私人笔记、实际报告和日志一起打包。

## 想看看里面怎么工作

入口是 [SKILL.md](SKILL.md)，文案审查见 [content-review.md](references/content-review.md)，本地记忆与反馈学习见 [local-learning.md](references/local-learning.md)，页面核验见 [verification-and-delivery.md](references/verification-and-delivery.md)。

在仓库根目录可运行以下检查：

```powershell
python scripts/check_package.py
./scripts/test_word_report.ps1 -WorkDir "$env:TEMP/word-report-synthetic-test"
```

前者检查发布文件、本地引用、Python 语法和常见泄露特征；后者用合成 Word 模板检查格式提取、缓存、目录、混合格式拒绝和原文件保护。它们不能代替真实报告的审稿与逐页验收，也不能证明所有宿主的兼容性。

内置生成器适合从明确指定的段落开始替换到文末；任意局部修改或复杂格式迁移需要额外的受限适配。完成质量也取决于所用模型、材料和模板，遇到缺失证据会明确留空或说明，不会靠编造内容把报告凑满。
