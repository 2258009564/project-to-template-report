# Private local memory and feedback learning

Resolve the local root from CODEX_HOME, otherwise the current user's ~/.codex. Private records live outside the distributable skill in <local root>/memories/extensions/ad_hoc/notes/. Search markers `word-report-profile-v1` and `word-report-learning-v1` and read only relevant notes at task start. Append small timestamped Markdown notes; do not edit MEMORY.md, summaries or previous notes. Missing records alone must not block the task when current materials resolve required personal fields; otherwise the mandatory identity gate in [local profile lookup](local-profile.md) applies and report work must pause for the user response.

Reuse consistent sourced name, student ID and other academic fields without repeated questions. Each remembered field needs a value, source, date and evidence or explicit user statement. Keep the user separate from teammates. Teachers, assignment dates, course titles and group membership are not personal defaults. Current explicit instructions override memory; inspect conflicting supplied evidence before asking only about unresolved fields. New correction notes identify superseded facts.

When ongoing personalization is authorized in a local record, learn from explicit feedback during each Word task without requesting permission again. Otherwise apply feedback to the task and persist only on explicit request. Respect exclusions and later revocation. Fix the current draft first, then before ending the turn append a `word-report-learning-v1` note with date, minimal paraphrase of feedback, scope, actionable rule, verification evidence/status and superseded record if any. Distinguish one-document requests from lasting preferences; ambiguous feedback stays task-scoped. Avoid duplicate notes. At the next relevant task, apply active rules and include them in review criteria. Unverified lessons stay pending; saving a note does not prove repair success.

Keep personal values, corrections, source paths and personalized preferences out of skill files, examples, assets and exported packages. Store no passwords, tokens, signatures, unrelated document contents or teammates' private data. Requested identity fields may appear in the user's document; private memory notes must not accompany deliverables. Before publication inspect the actual release file set, including fixtures, hidden files and caches, for private data. Use synthetic public examples. Do not claim publication safety without that inspection.

This learns by retrieving local records on future runs, not by training model weights or running between chats. Do not promise recall if records are unavailable.

Local storage means the private notes stay outside the distributable skill; never publish or attach them. This does not guarantee that personal information stays off the network: relevant fields may be included in requests to the configured model service during report generation. Explain this distinction when describing privacy. For an authorized profile update, save confirmed reusable values with source/date before resuming; future recall depends on accessible local notes and must not be claimed as verified until a later task actually retrieves them.
